# 韓国語カード

iPhone で使う個人用の韓国語暗記アプリです。PWA として作っています。

- **モード：** 学習（Quizlet の Learn 相当）、単語カード、テスト、スペル（聞き取り）、マッチの5つ
- **表紙：**
  - 連続学習の記録（今週の7日）
  - 記憶の予測（このまま復習しなかったら、学習した単語がどれくらい残りそうか）
  - 「今日の復習」。忘れかけている単語を全部の課から自動で選び、1日の上限は設定で 30／50／100 枚
- **検索：** 表紙の右上の虫めがねで、全カードを韓国語・日本語のどちらでも探せます。空白・全角半角・「～」の違いは無視します。
- **課の選び方：** 「学習する」やモードのボタンを押した先のページで、課（丸の中に番号）と種別を選びます。
  - 学習の途中のラウンドがあれば「続きから」を出します。
  - 新しく始めるときは、途中の続きが消えることを確認してから始めます。
- **カード：** 第1〜22課と会話表現、全2114枚を同梱
- **保存：** 進捗は端末内（IndexedDB）に保存します。回答するたびに保存するので、途中で閉じても続きから再開できます。
- **オフライン：** 一度開けば、アプリ本体とカードデータは電波がなくても使えます。
- **構成：** ビルド工程はありません。素の HTML / CSS / JavaScript（ES Modules）なので、GitHub Pages にそのまま置けば動きます。

## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作ります（例：`korean-cards`）。無料プランで公開する場合は Public にします。
2. このフォルダの中身をリポジトリに push します。`node_modules/` と `test-results/` は `.gitignore` で除外済みです。
   ```bash
   git init
   ```
   ```bash
   git add -A
   ```
   ```bash
   git commit -m "初版"
   ```
   ```bash
   git branch -M main
   ```
   ```bash
   git remote add origin https://github.com/<ユーザー名>/korean-cards.git
   ```
   ```bash
   git push -u origin main
   ```
3. GitHub のリポジトリ画面で **Settings → Pages** を開きます。
4. **Build and deployment** の Source を「Deploy from a branch」にし、Branch を `main`、フォルダを `/ (root)` にして Save します。
5. 1〜2分待つと、`https://<ユーザー名>.github.io/korean-cards/` で開けるようになります。

ファイルはすべて相対パスで参照しているので、サブフォルダ（`/korean-cards/`）で公開しても動きます。

## iPhone のホーム画面に追加する

1. iPhone の **Safari** で、公開した URL を開きます。Chrome など他のブラウザではホーム画面アプリになりません。
2. 画面下の共有ボタン（四角から矢印が出ているアイコン）をタップします。
3. **「ホーム画面に追加」** をタップし、右上の「追加」を押します。
4. ホーム画面の「韓国語カード」から起動すると、アドレスバーのない全画面で開きます。

補足：

- **データの保存場所：** Safari とホーム画面のアプリでは、保存場所が別々です。進捗を引き継ぎたいときは、設定の「バックアップを書き出す」→「バックアップから復元」を使います。
- **読み上げ：** 韓国語の音声がない場合は、iPhone の **設定 → アクセシビリティ → 読み上げコンテンツ → 声 → 韓国語** から追加します。
- **文字の大きさ：** iPhone の設定（画面表示と明るさ → テキストサイズ）に合わせて変わります。

## カードデータを更新する

方法は2つあります。どちらの場合も、カードIDは「課＋種別＋用語＋定義」から作っているので、内容が変わっていないカードの進捗はそのまま引き継がれます。

### A. アプリの設定から読み込む（その端末だけ）

1. 新しい md ファイルを iPhone の「ファイル」アプリに保存します。
2. アプリの **設定 → データ → カードデータ（md）を読み込む** で、そのファイルを選びます。
3. 読み込んだ枚数と、追加・削除された枚数が表示されます。
4. 元のデータに戻すときは「同梱のカードデータに戻す」を押します。

### B. 同梱データを差し替える（全端末に反映）

1. `data/cards.md` を新しいファイルで置き換えます。
2. `sw.js` の `VERSION` を上げます（下の「アプリを更新するとき」を参照）。
3. commit して push します。

md の形式：

- ` ```text ` ブロックの中に、1行1カードで書きます。
- 列は Tab 区切りで「課・種別・用語・定義」の順です。
- 1行目は見出し行です。

## アプリを更新するとき（大事）

コードやデータを変えて push するときは、**必ず `sw.js` の `VERSION` を上げてください。**

```js
const VERSION = 'v1.0.1'; // ← 変更のたびに上げる
```

- Service Worker はアプリ本体をキャッシュしています。`VERSION` が同じままだと、iPhone に古いファイルが残り続けます。
- 新しいバージョンは、更新後にアプリを1回開いた後、**次に起動したとき**から使われます。
  - 学習中に勝手に画面が入れ替わらないよう、自動で再読み込みはしません。
- 設定画面の下に出るバージョン表示は、`js/state.js` の `APP_VERSION` です。合わせて上げておくと、どちらが動いているか分かります。
- ファイルを追加・削除したときは、`sw.js` の `APP_FILES` も直します。漏れは `npm test` で検出できます。

## 読み上げ音声

- **収録音声：** 韓国語の読み上げは、Mac の「Yuna（プレミアム）」で前もって作った音声（`audio/*.m4a`、約2,100個・約25MB）を再生します。音声がない文や、設定で「端末の声」を選んだときは、端末の読み上げ（Web Speech API）を使います。
- **作り方：** Mac で `node tools/make-audio.mjs` を実行します。
  - 冒頭0.4秒・末尾0.2秒の無音を入れ、読み上げの区切り（「/」「·」）ごとに1ファイル作ります。
  - ファイル名は文のハッシュで、一覧は `audio/manifest.json` です。
  - 事前に、システム設定 → アクセシビリティ → リーダーと読み上げ → 声 で「Yuna（プレミアム）」を入れておきます。
- **カードデータを差し替えたとき：** もう一度実行すると、足りない音声だけ作り、使わなくなった音声は消します。あわせて `sw.js` の `VERSION` を上げてください。
- **端末への保存：** 一度聞いた音声は端末に保存され、オフラインでも鳴ります。設定 →「音声をまとめて保存」で全部を先に保存できます。この保存先はアプリを更新しても消えません。

## 同期（Firebase）

設定 → 同期 でメールアドレスとパスワードでログインすると、進捗と設定を Firestore に保存し、ほかの端末と共有します。

- **保存の主は端末内（IndexedDB）：** オフラインでも今までどおり動き、電波が戻ると同期します。
- **同期のタイミング：** 変更の数秒後、アプリを開いたとき、アプリを閉じるとき。
- **2台で使ったときのまとめ方：**
  - 進捗はカードごとに新しいほうを残す。
  - マッチの記録は速いほうを残す。
  - 設定などは最後に変えたほうを残す。
  - 「進捗をリセット」「バックアップから復元」はほかの端末にも反映される。
- **使っている Firebase の機能：** Authentication（メール / パスワード）と Firestore。SDK は使わず REST API で呼んでいる（`js/firebase.js`）。
- **データの置き場所：** `users/{uid}/data/{key}`。ルールで本人だけが読み書きできる。
- **設定値：** `js/config.js` の `FIREBASE`。
  - `apiKey` は公開して使う前提の値で、データはセキュリティルールで守る。
  - GitHub から「API キーが公開されている」という通知が来ることがあるが、Firebase の Web 用キーなので問題ない。
  - 気になる場合は、Google Cloud コンソールでキーの利用元を `https://isshin-4869.github.io/*` に制限する。
- **アカウント：** Firebase コンソールの Authentication で作る。新規登録はオフにしてあるので、アプリからは作れない。

## ウィジェット

連続記録・今週学習した日・今日の復習の残り枚数・記憶の予測を、iPhone のホーム画面・ロック画面に出せます。PWA はウィジェットを作れないので、無料アプリ「Scriptable」を使います。

使うには、設定 → 同期 でログインしていることと、`js/config.js` の `PUSH.workerUrl`（通知と同じ Cloudflare Worker）が入っていることが必要です。

### アイコンのバッジ

- アプリのアイコンに、**今日の復習の残り枚数**（1日の上限から今日もう復習した分を引いた数）が数字で出ます（0 のときは消えます）。アプリを開くたびに数え直します。
- iPhone では、ホーム画面に追加したアプリで **通知を許可** したときだけ表示されます（設定 → 通知 を一度オンにする）。

### Scriptable の設定

1. App Store で **Scriptable**（無料）を入れます。
2. アプリの **設定 → ウィジェット** で「ウィジェットの URL を作る」を押し、出てきた URL を「コピー」します。
3. Scriptable を開いて右上の「+」を押し、[`widget/scriptable-widget.js`](widget/scriptable-widget.js) の中身を全部貼ります。
4. 先頭近くの `STATS_URL = "…"` の `"…"` の中を、コピーした URL に置き換えます。
5. 上の題名をタップして名前を「韓国語カード」にし、「完了」で保存します。▶ で試すと、中サイズの見本が出ます。
6. ホーム画面を長押し → 「編集」→「ウィジェットを追加」→ **Scriptable** → 小 か 中 を追加します。
7. 追加したウィジェットを長押し → 「ウィジェットを編集」→ **Script** に「韓国語カード」を選びます。
8. ロック画面に置くときは、ロック画面を長押し → 「カスタマイズ」→ ウィジェットの枠 → Scriptable を選び、同じように Script を選びます。

表示する内容：

| サイズ | 内容 |
|---|---|
| 小 | 連続日数（「12日連続」）と今日の復習の残り枚数 |
| 中 | 左：連続日数と今週の 7 日（学習した日は色付き、今日でまだの日は枠だけ）／右：今日の復習の残り枚数と、記憶の予測のグラフ（今日〜7日後、点線は「忘れかけ」の 60%） |
| ロック画面（丸） | 連続日数 |
| ロック画面（四角） | 連続日数と復習の残り枚数 |
| ロック画面（1行） | 「12日連続・復習 N枚」 |

- 配色はアプリと同じライト・ダークの 2 色（アクセントは 1 色）で、端末の外観に合わせます。
- 今日の復習が終わると「今日の復習 おわり」、復習どきの単語がなければ「復習はありません」と出ます。
- 圏外などで読めなかったときは、前回の値を「前回の値」と添えて出します。日付が変わっていたら、連続日数・今週・復習の枚数は分かる範囲で今日の値に直します（復習の枚数は目安）。
- 古い形（惑星の版）の要約しか届いていないときは「アプリを開いて更新してください」と出ます。アプリを開けばまもなく新しい形が届きます。
- タップしたときの動きは、スクリプト先頭の `TAP` で変えられます（既定は何も開かない）。

### データの流れ

1. アプリ：進捗・学習した日・設定が変わったときと、アプリを開いたときに、要約（`v: 2`）を Worker の `POST /summary` に送ります（Firebase の ID トークン付き）。
   - 送るのは中身が変わったときだけで、多くても 2 分に 1 回です。アプリを閉じるときは待たずに送ります。
2. Worker：要約を KV（`widget:<uid>`）に置きます。最初の 1 回で、推測できない token（43 文字）を作ります。
3. Scriptable：`GET /widget/<token>` で要約を読んで表示します。記憶の予測のグラフは Scriptable の中で線を引いて描きます。
   - ウィジェットの更新間隔は iOS が決めます（目安 15 分〜1 時間）。

### プライバシー

- Worker に置くのは、連続日数・今週の学習した日・復習の枚数（残り・済み・上限・復習どき）・記憶の予測（8 つの %）・学習した枚数だけの小さな要約（2KB 未満）です。カードの中身やメールアドレスは送りません。
- ウィジェットの URL はログインなしで読めます。**URL がパスワードの代わり** なので、人に見せないでください。
- 漏れたかもしれないときは、設定 → ウィジェット →「URL を作り直す」を押します。古い URL はすぐに使えなくなるので、Scriptable の `STATS_URL` を新しい URL に貼り替えます。

## 通知（Cloudflare Workers）

設定 → 通知 の「毎日のリマインダー」をオンにすると、決めた時刻にその日まだ学習していなければ通知が届きます。

- **使える条件：** iPhone は iOS 16.4 以降で、ホーム画面に追加したアプリから使えます。同期でログインしている必要があります。
- **仕組み：**
  - Worker（`worker/`、`https://korean-cards-push.isshinryu4869.workers.dev`）が毎時0分に動き、時刻が合う人に中身なしの push を送ります。
  - 文面は端末の Service Worker が、端末内の進捗から作ります。
  - その日に学習していれば、アプリが Worker に知らせるので、その日の通知は送りません。
- **認証：** Worker への登録には Firebase の ID トークンを使い、Worker 側で署名を確かめます。
- **鍵の置き場所：** VAPID の秘密鍵は Worker の secret（`VAPID_PRIVATE_JWK`）と、手元の `~/.config/korean-cards/vapid.json` だけに置きます。リポジトリには入れません。
- **Worker を更新するとき：** `worker/` で次のコマンドを実行します。トークンは `~/.config/korean-cards/cloudflare-token` に置いてあります。
  ```bash
  CLOUDFLARE_API_TOKEN=$(cat ~/.config/korean-cards/cloudflare-token) npx wrangler@4 deploy
  ```
- **テスト：** `node --test worker/test/*.test.mjs` で実行できます（`npm test` にも含まれます）。
